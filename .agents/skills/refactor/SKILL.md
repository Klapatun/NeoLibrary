# Скил: рефакторинг Neo Library (refactor)

Роль: я рефакторю продакшн-код **только** по утверждённому тикету `[REFAC]`
из `ISSUES.md`. Это отдельный поток конвейера (`PIPELINE.md` §3): запускается
по требованию человека, после меня подключается тестировщик (T) — он
проверяет сьют. Мой собственный прогон после каждого шага — safety net, а не
замена проверки T.

## 1. Входные условия

1. В `ISSUES.md` есть тикет `[REFAC]` с целевой архитектурой, шагами,
   анти-рекомендациями и инвариантами, и план согласован (строка «Статус»).
   **Тикета нет → стоп**: тикет — зона скила `analytics` (либо я черну его
   в том же формате, но утверждение плана — за человеком до начала работ).
2. Раздел «Текущее состояние» тикета **сверен с кодом**: тикету может быть
   неделя, а код сдвинулся. `git status` + mtime файлов до любой правки
   (правило ISSUES 10.2). Если состояние устарело — обновить его (с
   человеком) и только потом начинать.
3. Перед любым Gradle-запуском (PowerShell):
   ```powershell
   $env:JAVA_HOME = "D:\Program Files\Android\Android Studio\jbr"
   ```

## 2. Инварианты рефакторинга (PIPELINE.md, CONTEXT.md)

- **Поведение не меняется**: все существующие тесты проходят **без
  изменений**; набор тестов не меняется. Тест «мешает» рефакторингу —
  это признак, что рефакторинг сломал контракт → стоп → к человеку. Тесты я
  НЕ правлю (в том числе не «адаптирую»).
- **Публичный API рефакторящихся классов не меняется** (публичные и
  package-private методы — часть контрака; именно это делает существующие
  тесты safety net'ом).
- **Один шаг = один коммит** (сообщение: «Шаг N: …»); полный сьют зелёный
  после **каждого** шага — до перехода к следующему.
- Стиль не менять: pre-lambda (анонимные классы) — никаких «попутных
  модернизаций» на лямбды/стримы; без новых зависимостей, без AndroidX,
  нет API выше 19, Holo.
- **Без «заодно»**: проблема, найденная вне тикета, → новый тикет в
  `ISSUES.md`, а не попутный фикс. То, что рассматривалось и отклонялось, —
  записывать в анти-рекомендации тикета (см. §4), а не делать по-тихому.

## 3. Работа по шагам

1. Внести шаг тикета (один коммит).
2. Проверить:
   ```powershell
   gradlew.bat :app:testDebugUnitTest   # полный сьют — всё зелёное, то же число тестов
   gradlew.bat :app:lintDebug           # 0 errors
   gradlew.bat :app:assembleDebug       # если шаг задевал ресурсы/сборку
   ```
3. **Правило флейков** (скил `tests` §2–3, ISSUES 8.4): таймаут случайного
   теста в полном сьюте — не регресс, пока не доказано противное: сначала
   изолированный прогон упавшего теста (`--tests "…Класс.метод"`), только
   затем выводы.
4. Только когда шаг зелёный — следующий шаг.
5. В конце: обновить раздел «Текущее состояние» тикета (шаги N выполнены,
   осталось M) и передать конвейер тестировщику (T) на финальную проверку.

## 4. Шаблон тикета (эталон)

`[REFAC]` «Разрастание `MetaExtractor` и `CoverExtractor` — декомпозиция»
(`ISSUES.md`):

- **Диагностика**: «толстые фасад-классы», таблица конкретного дублирования
  (`findOpfPath`, `readFb2Entry`, `readToEndBytes`/`readZipEntry*` — в обоих
  классах; перечисление форматов в 4 местах).
- **Целевая архитектура, шаги 0–3** (каждый — отдельный коммит без изменения
  поведения; публичный API `MetaExtractor.extract`/`CoverExtractor.extract`/
  `canHaveCover` и все тесты не меняются):
  - Шаг 0: `canHaveCover` → `Formats.canHaveCover(String)` (Formats —
    объявленный single source of truth);
  - Шаг 1: `meta/ZipUtil` (package-private) — весь ZIP/IO-плаггинг;
  - Шаг 2: один ридер на формат по прецеденту `MobiParser` (`meta/EpubPackage`,
    `meta/Fb2Reader`); MOBI-байтовые утилиты → `MobiParser`;
  - Шаг 3: тонкие фасады (~40/~30 строк, dispatch + `notFound`).
- **Анти-рекомендации** (рассмотрено и отклонено): единый `BookReader`
  (сканеру нужна только мета, `CoverLoader` — только обложка — два фасада =
  два сценария); интерфейсы-стратегии (полиморфизма нет, dispatch по
  расширению); сабпакеджи (преждевременно, делить при 10+ классах); лямбды
  (стиль — инвариант); новые зависимости (запрещено инвариантом).
- **Invariants**: minSdk 19 / Holo / без AndroidX и зависимостей; публичный
  API фасадов не меняется → `MetaExtractorTest` (18) + `CoverExtractorTest`
  (18) проходят без правки — safety net; рефакторинг не меняет поведение —
  после каждого шага сьют зелёный.
- **Запуск**: с шага 0 или 1 (оба наиболее безопасны; шаг 1 сразу убирает
  самое густое дублирование).
