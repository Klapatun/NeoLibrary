# Скил: разработка Neo Library (develop)

Роль: я пишу **продакшн-код** (`app/src/main/**`). Мой вход: утверждённый
план `.agents/plans/<feature-name>/PLAN.md` (статус «план согласован»;
`<feature-name>` — имя ветки, `/` заменено на `_`) и **тесты, которые уже
написал тестировщик** (на этот момент — RED). Тесты — это спецификация
задачи (конвейер в `PIPELINE.md`, test-first: аналитик → тестировщик → я).

Границы:
- Новые тесты не пишу, тесты тестировщика **не меняю** — в том числе не
  «ослабляю», чтобы прошли. Тест «мешает» → стоп, к человеку.
- Рефакторинг/«заодно» вне плана не делаю: проблему, которую заметил,
  выношу тикетом в `ISSUES.md`, а не чиню попутно.

## 1. Предполёт (чек-лист до первой правки)

1. `git status` + mtime файлов, которые буду менять (ISSUES 10.2): грязное
   дерево / свежий mtime (минут 30–60) = вероятна параллельная сессия —
   свериться, а не переписывать.
2. Прочитать по порядку: `CONTEXT.md` (инварианты, class map, workflows) →
   тикет → **тесты тестировщика** (понять, что именно они ожидают — это и
   есть моё ТЗ). На этот момент тесты могут ещё не компилироваться
   (ссылаются на продакшн-код, которого нет) — это **не** повод останавливать
   работу: цель — превратить их в зелёные, а проверка «красноты» идёт после
   написания кода (§5).
3. Перед любым Gradle-запуском (Windows, `java` в PATH нет, JDK 17 при
   Android Studio), PowerShell:
   ```powershell
   $env:JAVA_HOME = "D:\Program Files\Android\Android Studio\jbr"
   ```

## 2. Правила кода (инварианты проекта)

- **Java, pre-lambda-стиль**: анонимные классы, без лямбд и стримов (Java 8
  доступен, но стиль — инвариант).
- **minSdk 19**: нет API выше 19 (lint `NewApi = error` в `app/lint.xml`),
  Holo-тема (Material требует API 21+), нет support-библиотек (ViewPager и
  пр. — под запретом).
- **Без AndroidX / без сторонних runtime-зависимостей** — только Android
  framework + JDK (`java.util.zip`, `XmlPullParser`); билд офлайн.
- **Manifest**: без атрибута `package`; у каждого `<activity>` —
  `android:exported`; `namespace com.example.mylibrary` в `app/build.gradle`.
- Файл книги никогда не остаётся полудописанным: всегда `.tmp` → swap → `.bak`.
- `BookDatabase.upsert`/`upsertBasic`/`updateMetadata` не затирают
  `last_read`; `updateMetadata` не затирает `user_edited` (enricher их не
  перетирает).
- `Formats.ALL` — single source of truth (скан/фильтр/бейдж); состав форматов
  меняется вместе с `FormatsTest` (это зона тестировщика — согласовывать).
- Обогащение: per-file бюджет 2 минуты, один висящий файл не зацикливает
  очередь; порядок очереди — дешёвые форматы первыми
  (`Formats.enrichmentPriority`: EPUB/FB2 → FB2ZIP → MOBI → остальное),
  `meta_failed` — самые последние.

## 3. Дисциплина коммитов

- **Один шаг плана = один коммит**; в сообщении — что сделал шаг.
- Коммит шага — когда тесты этого шага проходят; в конце задачи — **полный
  сьют зелёный**.
- Изменился задокументированный факт (class map, workflow, инвариант —
  `CONTEXT.md`; UI-числа и иконки — этот скил, §6–7) → обновить документ тем же
  коммитом (прецеденты расхождения: ISSUES 6.5, 13.2 — доки правились от
  устаревшей версии кода).
- Lint проверять до коммита (pre-commit-хук и так его гоняет).

## 4. Дерево решений при проблемах

| Проблема | Действие |
|---|---|
| Задача заблокирована: план не реализуем, впереди инвариант, тест не сделать честным путём, crash/потеря данных | **Стоп → сразу к человеку** |
| Тест тестировщика ошибочен / противоречит плану или реальности | **Не трогать** тест → к человеку (правит тестировщик по согласованному изменению плана) |
| Новая проблема **низкого** приоритета (не блокирует задачу, не бьёт по инвариантам) | **Новый тикет в `ISSUES.md`** (`[FIX]`/`[IMPROVE]`, низкий) → продолжить задачу |
| Улучшение «заодно», которого нет в плане | Не делать; максимум — тикет в `ISSUES.md` |

## 5. Верификация перед push

```powershell
gradlew.bat :app:testDebugUnitTest   # весь сьют зелёный (тесты тестировщика + все существующие)
gradlew.bat :app:lintDebug           # 0 errors
gradlew.bat :app:assembleDebug       # APK, если задевал сборку/ресурсы
```

- **Проверка «красноты» тестов — после написания кода по задаче** (не до):
  в начале задачи тесты по определению красные (и могут даже не
  компилироваться — это нормально, моя цель — превратить их в зелёные).
  Если после написания кода тест всё равно не компилируется или падает по
  ошибке, которая сидит в самом тесте (не в моём коде), — это не мой фикс:
  к человеку (тесты — зона тестировщика).
- **Правило флейков** (скил `tests` §2–3, ISSUES 8.4): таймаут случайного
  теста в полном сьюте — **не** регресс, пока не доказано противное. Сначала
  повторить упавший тест в изоляции (`--tests "...Класс.метод"`): изолированно
  за секунды — это флейк (голод фоновых тредов пула AsyncTask). Не «чинить»
  код по первому таймауту и не поднимать `WAIT_MS` без основания.
- Push: хук `pre-push` сам гоняет сьют и роняет push с красным; `--no-verify`
  ради флейка — не обходить, повторить на тихой машине/в изоляции.

## 6. Детали UI (грид, пагинация, свайп)

Детали раскладки и жестов живут здесь (в `CONTEXT.md` остаётся только
указатель на этот раздел — см. `PIPELINE.md` §5).

### Режимы вида (список/плитки)

- `MainActivity` показывает один и тот же `BookAdapter` в `ListView` и
  `GridView` (`activity_main.xml`); переключатель (`@+id/toggle_view`) —
  `setViewMode()` (смена видимости + какой layout инфлятит адаптер).
- **Плитки — режим по умолчанию**: грид стартует видимым, адаптер прикреплён
  к гриду в `onCreate` (и **до `setAdapter` принудительно
  `adapter.setMode(initialMode)`** — регрессия 9.3: class-дефолт `MODE_LIST` +
  ранний выход в `setViewMode` = первый layout в чужом макете).
- Выбор режима персистентен: `SharedPreferences` (файл `library_prefs`, ключ
  `view_mode`) — переживает и ротацию, и закрытие приложения.
- Плитки: `GridView`, 3 колонки, тайл `item_book_grid.xml` — обложка сверху,
  бейдж формата (`bg_format_badge`) в левом нижнем углу обложки, заголовок
  под обложкой (2 строки); все тайлы одного размера.
- Грид разбит в **px** под ONYX Boox Volta 3 (6", 1024x758): тайл 242px
  (`stretchMode=none`, `columnWidth=242px`), зазоры 8px между колонками и
  строками, `numColumns="auto_fit"`: портрет 758px → 3 колонки
  (3×242 + 2×8 = 742px), ландшафт 1024px → 4; контейнер книг — 16px padding
  сверху, 8px по бокам; обложка 242x328px, красный круг 155px
  (`bg_circle_red`) с инициалом для книг без обложки; скроллбар `insideOverlay`.

### Пагинация (кебаб «Add/Remove pagination»)

- Checkable-пункт кебаба (`main_menu_pagination`); при включении — стрип
  `@+id/pagination_bar` (Prev / «X / Y» / Next). Кнопки — `ImageButton` 16dp
  (`page_prev`/`page_next`); disabled-состояние — селектор с потускневшим PNG
  (`#999999`): `android:alpha` на `<item>` селектора требует API 21 — на 19
  только отдельный PNG.
- Адаптер выдаёт **одну страницу за раз** — клиентское окно по ВСЕМУ курсору
  (`BookAdapter.setPagination`), поэтому любое изменение каталога (скан,
  enrich, импорт, удаление, фильтр) ребайдится как раньше, и прямые
  rebind-пути `MainActivity` (`changeCursor(currentCatalogCursor())` +
  `updateEmptyView()`) работают без изменений.
- Размер страницы: грид — фиксированные **6 тайлов** (`GRID_PAGE_SIZE`);
  список — «столько строк, сколько помещается на экране»
  (`computeListPageSize()`). Высота книжной области меняется под пальцами
  (stage-2 стрип, пейджер-стрип, первый layout) → `OnLayoutChangeListener` на
  `bookContainer`: новое значение ВЫСОТЫ → **posted**-рекомпьют (читает
  осевшую высоту, не уведомляет адаптер в середине layout-пасса).
- Выбор персистентен: `library_prefs`, ключ `pagination_enabled`;
  применяется в `onCreate` **ПОСЛЕ** режима вида (размер страницы от него
  зависит).
- `changeCursor` зажимает page до последнего существующего **ДО**
  `super.changeCursor` (dataset-колбэки видят зажатый page); свап на
  НЕ-NULL курсор шлёт `onChanged`, НЕ `onInvalidated` (тот — только для
  `changeCursor(null)`). Пустой каталог — 0 страниц, стрип скрыт.
- **Свайп** страниц (когда пагинация включена): горизонтальный свайп по
  list/grid (влево = +1, вправо = −1). `PagedListView`/`PagedGridView`
  (subclass'ы `ListView`/`GridView`): жест детектится в override
  `dispatchTouchEvent`, питающем `PageSwipeTracker` (свайп = на release
  |dx| ≥ 3×touchSlop и |dx| ≥ 2×|dy|; второй палец отменяет); смена страницы
  **постится** (выполняется после полного развёртывания touch-последовательности)
  и идёт через тот же `showPage()` (clamp + скролл наверх + индикатор).
  **Подводный камень API 19**: `OnTouchListener` на списке НИКОГДА не
  срабатывает для свайпа, начатого на строке (кликабельная строка поглощает
  жест до listener'а списка) — отсюда override'ы
  `dispatchTouchEvent`/`onInterceptTouchEvent`. Список перехватывает жест в
  тот момент, когда он пересёк порог свайпа (`onInterceptTouchEvent` → true,
  фреймворк шлёт строке `ACTION_CANCEL`) — иначе на API 19 свайп, не выходящий
  за границы строки, разрядился бы в клик по строке («Open this book?»).
  Тапы и дрожь ниже порога перехвату не подвергаются.

## 7. Иконки (SVG → PNG)

- Шесть иконок хедера (`ic_import`, `ic_refresh`, `ic_grid`, `ic_list`,
  `ic_overflow`, `ic_filter`/`ic_filter_active` — воронка фильтра;
  `ic_filter_active` — та же воронка + акцентная точка в правом верхнем углу
  (12px из 48, #E74C3C), состояние «фильтр настроен») создаются как SVG в
  `app/icons/` (48×48, белые, прозрачные — точка единственное цветное пятно;
  состояния — отдельными PNG, на API 19 без рантайм-оверлеев). Кebab
  (`ic_overflow`) — правый угол хедера, вытеснил кнопки
  Import/Rescan из строки хедера; его popup (`res/menu/main_menu.xml`):
  **Import**, **Rescan**, checkable **Add/Remove pagination** (title +
  checkmark отражают состояние, выставляются в `showHeaderMenu`), **Clear
  library** (диалог подтверждения, `db.clear()` — строки + кэш обложек,
  файлы на диске не трогаются).
- Рантайм-PNG — `app/src/main/res/drawable/` (32×32, размер 32dp кнопки
  хедера) — генерируются из SVG через `tools\generate-icons.ps1` (ведёт
  `tools/SvgToPng` — маленький dependency-free .NET-растеризатор: OS WIC SVG
  падает на этой машине, а сторонние растеризаторы запрещены правилом «без
  лишних зависимостей»).
- Генератор **суперсэмплирует**: рендерит SVG в 96×96 (2× источника) и
  сжимает к 32 точным 3×3 area-average — границы 32px такие же чёткие, как у
  векторного источника.
- **PNG закоммичены** (билд на 100% офлайн); инструмент запускается только при
  редизайне иконки. VectorDrawable в рантайме — не вариант (API 19 < 21).
- Row-иконки `ic_kebab`/`ic_kebab_gray` (96px) **не имеют** SVG-источников
  (ISSUES 9.4): при перерисовке — либо создать SVG и прогнать генератор,
  либо править PNG вручную.
